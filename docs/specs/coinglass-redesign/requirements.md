# Requirements — coinglass-redesign

승인 이력: 사용자 제공 디자인 참고자료(`coinglass-Design-System.zip`, coinglass.com에서 추출된 브랜드 토큰·컴포넌트 킷) 기반 인터뷰(AskUserQuestion 4라운드) + 브레인스토밍 시각 컴패니언 목업 승인(2026-08-03).

## 배경

기존 `dashboard-mvp`는 "Ollama 스타일"(`docs/steering/design.md`) — UI 크롬은 흑백만, 색은 데이터 잉크에만, 알약형 버튼, 라이트모드 온리를 원칙으로 구현됨. 사용자가 coinglass.com의 디자인 시스템 참고자료를 제공하며 "이 파일을 참고하여 디자인을 개편해줘"라고 요청. 인터뷰 결과, 시각 스타일뿐 아니라 GNB·티커바 등 구조적 요소까지 coinglass 톤으로 재구성하기로 결정됨. 단, todayfin은 12개 고정 지표를 다루는 개인 대시보드이지 coinglass 같은 멀티에셋 트레이딩 터미널이 아니므로, coinglass의 정보 구조를 문자 그대로 복제하지 않고 todayfin의 실제 지표 분류(4섹션)에 맞게 번역해 적용한다.

## R1. 색상·형태 토큰 전환

- WHEN UI 크롬(GNB·버튼·활성 탭·배지·포커스링·링크)을 렌더링하면 THEN 시스템은 coinglass 네이비(`#12467b` 라이트 / 다크 보정값)를 주요 액센트 컬러로 전면 사용해야 한다 (기존 "UI는 흑백만" 원칙 폐기)
- WHEN 카드·버튼·모달·배지 등 컴포넌트를 렌더링하면 THEN 시스템은 모서리 반경을 8px(라운드 사각형)로 통일해야 한다 (기존 12px 카드 / 9999px 알약형 버튼 폐기)
- IF 등락 표시(상승/하락)·이동평균선(MA)·수급 3주체 라인 등 데이터 잉크 색상을 렌더링하면 THEN 시스템은 라이트/다크 테마와 무관하게 완전히 동일한 색상 값을 사용해야 한다 (상승 `#d60000`, 하락 `#0051c7`, MA1 `#f59e0b`/MA2 `#10b981`/MA3 `#8b5cf6` — 2026-08-03 사용자 피드백: "등락표시는 빨간색과 파란색 그대로 유지"로 확정, 테마별 대비 보정을 위한 톤 변경 금지)
- WHEN 등락 텍스트(카드·티커의 `+5,920억원` 형태)가 다크 테마에서 렌더링되면 THEN 시스템은 색상 값은 유지하되 `font-weight`를 600 이상으로 적용해 최소 시인성을 확보해야 한다 (다크 배경 대비 WCAG 미달 기록 — `design.md` 참조, 색상 자체는 변경하지 않음)
- WHEN 배경·표면·테두리·본문 텍스트 등 UI 크롬 색상을 렌더링하면 THEN 시스템은 활성 테마(라이트/다크)에 따라 다른 값을 사용해야 한다

## R2. GNB (신규)

- WHEN 페이지가 로드되면 THEN 시스템은 기존 `.app-header`(로고+갱신시각만 있던 다크 바)를 대체하는 GNB를 렌더링해야 한다. GNB는 로고(`todayfin`), 4개 카테고리 탭(수급 / 시장 가격·추세 / 거시·통화 / 원자재), 다크모드 토글, 마지막 갱신 시각을 포함해야 한다
- WHEN 사용자가 GNB의 카테고리 탭을 클릭하면 THEN 시스템은 해당 섹션으로 부드럽게 스크롤 이동해야 한다 (별도 라우트/페이지 전환 없음 — 홈은 여전히 단일 스크롤 페이지)
- WHEN 사용자가 스크롤하면 THEN 시스템은 현재 뷰포트에 걸린 섹션에 대응하는 GNB 탭을 활성 상태(네이비 텍스트+밑줄)로 자동 갱신해야 한다
- WHEN 뷰포트가 640px 이하이면 THEN GNB 탭 영역은 가로 스크롤 가능해야 한다 (탭 줄바꿈 금지, 가로 스크롤 허용)

## R3. 티커 바 (재도입)

- WHEN GNB 아래 영역이 렌더링되면 THEN 시스템은 전 지표(12종)를 요약해 우→좌로 흐르는 무한 스크롤 티커 바를 표시해야 한다 (2026-08-03 3차 피드백으로 보류됐던 기능 재도입 — 이전 구현은 커밋 `a7789d7`에 보존되어 있으며, 이번 재도입 시 coinglass 톤(네이비/8px)으로 재스타일링해 새로 구현한다)
- WHEN 사용자가 티커 바 위에 마우스를 올리면 THEN 스크롤은 정지해야 한다
- IF 사용자의 OS가 `prefers-reduced-motion: reduce`를 요청하면 THEN 티커 바는 애니메이션 없이 정적으로 표시해야 한다
- WHEN 사용자가 티커 항목을 클릭하면 THEN 시스템은 카드 클릭과 동일하게 해당 지표의 상세 모달을 열어야 한다
- WHEN 티커 항목에 등락을 표시하면 THEN R1의 데이터 잉크 고정 원칙(라이트/다크 무관 동일 색상)을 따라야 한다

## R4. 다크모드 (신규)

- WHEN 사용자가 GNB의 다크모드 토글을 클릭하면 THEN 시스템은 전체 UI 크롬(배경·표면·테두리·텍스트·액센트)을 즉시 다크 테마로 전환해야 한다 (기존 "라이트모드 온리" 원칙 폐기)
- WHEN 사용자가 처음 방문하면 THEN 시스템은 OS `prefers-color-scheme`을 초기값으로 사용해야 한다
- WHEN 사용자가 테마를 전환하면 THEN 시스템은 선택을 `localStorage`에 저장하고 다음 방문 시 그 값을 우선해야 한다
- WHEN 다크 테마가 활성화되면 THEN 캔들·라인 차트(PriceChart/FlowsChart)의 배경·그리드·축 텍스트도 다크 톤으로 전환해야 한다 (R1에 따라 캔들/MA/수급 라인 색상 자체는 변경하지 않음)
- WHEN 상세 모달이 다크 테마에서 열리면 THEN 모달 배경·오버레이·기간선택 pill·MA 범례도 다크 톤을 따라야 한다

## R5. 카드·버튼 컴포넌트

- WHEN 지표 카드(IndicatorCard)를 렌더링하면 THEN 배경은 coinglass surface 톤(라이트 `#f5f5f5`, 다크 대응값), 모서리는 8px, hover 시 보더는 네이비 액센트로 강조해야 한다
- WHEN 기간 선택(3M/6M/1Y/3Y/5Y)·MA 토글 등 컨트롤을 렌더링하면 THEN 8px 라운드 사각형 pill을 사용해야 하며, 활성 상태는 네이비 배경+흰 텍스트여야 한다 (기존 알약형 대체)

## R6. 상세 뷰

- WHEN 카드 또는 티커 항목을 클릭하면 THEN 시스템은 기존과 동일하게 모달 오버레이로 상세 뷰를 열어야 한다 (2026-08-03 인터뷰에서 사이드바/페이지 전환 방식을 재검토했으나, "여러 지표를 그리드에서 비교하는 가치"를 지키기 위해 모달 유지로 확정 — 기존 dashboard-mvp R3 결정 재확인)
- 상세 뷰의 시각 스타일(카드·버튼·색상)만 R1/R5를 따라 개편하고, 차트 유형·MA 토글·기간 프리셋·크로스헤어 툴팁 등 기능은 변경하지 않는다

## R7. 회귀 방지

- 기존 `dashboard-mvp` requirements.md의 R1(지표 정의)·R2(수집)·기능적 R3 요구사항(요약 1회 fetch, 해시 라우팅, stale 표시, 반응형, 면책·출처 표기)은 이번 스코프에서 변경하지 않는다. 이번 스펙은 시각·네비게이션 개편만 다룬다
- WHEN 리디자인이 완료되면 THEN 기존 반응형 브레이크포인트(1280/850/640) 동작과 640px 모바일 가로 스크롤 없음 요구사항은 유지되어야 한다

## 비기능

- 순수 프론트엔드 변경 — `pipeline/`·`data/` 스키마·수집 로직 변경 없음
- 디자인은 `docs/steering/design.md`(coinglass 적응판으로 갱신) 토큰을 준수해야 한다
- 비용 0원 원칙 유지 (외부 폰트 CDN 등 새 유료/제한 의존성 도입 금지 — coinglass의 "XPK" 폰트는 실제 배포 자산이 없는 플레이스홀더이므로 채택하지 않고 기존 Pretendard Variable을 유지한다)

## 검증 계획

- 실제 브라우저(claude-in-chrome)로 라이트/다크 각각: 홈 GNB 탭 스크롤 연동, 티커 바 스크롤·hover 정지·클릭, 카드 hover, 상세 모달 기간/MA pill, 데이터 잉크 색상이 테마 전환 후에도 동일한지 스크린샷 대조
- 640px 모바일 뷰포트에서 GNB 탭 가로 스크롤, 카드 그리드 1열, 모달 풀스크린 확인
- 기존 vitest 단위 테스트(37개) 회귀 없음 확인 + 신규 로직(테마 훅 등) 테스트 추가
