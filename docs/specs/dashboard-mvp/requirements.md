## R2. 수집 (EARS)

- WHEN 장전 크론(KST 08:10, 월~토)이 실행되면 THEN 시스템은 preopen 프로필(usdkrw, usdjpy, ust2y, ust10y, ust30y, wti)만 수집해야 한다
- WHEN 장후 크론(KST 18:40, 평일)이 실행되면 THEN 시스템은 afterclose 프로필(수급 2종, 지수 2종, 종목 2종, ktb3y)만 수집해야 한다
- WHEN 소스 응답이 수신되면 THEN 시스템은 스키마·불변식 검증(OHLC 관계, 날짜 단조성, 결측·이상치)을 통과한 경우에만 기존 `data/{id}.json`을 교체해야 한다
- IF 검증이 실패하거나 응답이 비어 있으면 THEN 시스템은 기존 데이터를 유지하고 `meta.json`에 실패를 기록해야 한다
- WHEN 수집이 완료되면 THEN 시스템은 최근 5영업일 구간을 재수집·병합해 잠정치→확정치 갱신을 반영해야 한다
- WHEN 폴백이 필요하면 THEN 시스템은 R1의 정의와 동일한 소스로만 전환해야 하며, 동일-정의 소스가 없으면 stale 처리해야 한다
- IF 지표의 마지막 정상 관측일이 3영업일 이상 과거이면 THEN 워크플로우는 실패 상태로 종료해 운영자에게 알려야 한다 (휴장으로 인한 "새 데이터 없음"은 정상)

## R3. 화면 (EARS)

- WHEN 홈에 접속하면 THEN 시스템은 `summary.json` 1회 fetch로 4개 섹션(수급/시장/거시·통화/원자재)의 지표 카드(최신값·전일 대비·최근 3개월 미니차트·데이터 기준일)를 렌더해야 한다
- WHEN 카드를 클릭하면 THEN 시스템은 해시 라우트(`#/i/{id}`)를 반영한 모달 오버레이로 상세 뷰를 열고 `{id}.json`을 지연 로드해야 한다(페이지 전환 없이 홈은 배경에 유지 — 2026-08-03 피드백 반영, 좌측/상단 메뉴바 방식은 카드 그리드 일람 장점과 상충되어 채택 안 함)
- WHEN 상세 뷰가 열리면 THEN 시스템은 R1에 정의된 차트 유형·MA 토글·기간 프리셋(3M/6M/1Y/3Y/5Y)·크로스헤어 툴팁을 제공해야 한다
- IF 지표가 stale이면 THEN 시스템은 카드와 상세에 마지막 관측일과 함께 stale 상태를 명시해야 한다
- WHEN 헤더가 표시되면 THEN 시스템은 본문과 시각적으로 구분되는 배경(다크 톤)으로 렌더해야 한다(2026-08-03 피드백 반영 — 흑백·회색 톤 내에서 구분, `docs/steering/design.md`의 `--surface-dark`/`--on-dark` 참조)
- WHEN 홈 최상단(헤더와 "수급" 섹션 사이)이 표시되면 THEN 시스템은 알상무 콘텐츠 기획 의도를 요약한 소개 문구를 노출해야 한다(2026-08-03 피드백 반영)
- 모든 화면은 640px 모바일에서 가로 스크롤 없이 사용 가능해야 한다
- 모든 페이지는 면책 문구와 데이터 출처(사람이 읽는 원 출처명 — 어댑터 식별자 아님)를 노출해야 하며, 푸터에는 제작자(jelitz)와 GitHub·문의 이메일(info@jelitz.com)을 표기해야 한다(2026-08-03 피드백 반영)

티커 바 정책(2026-08-03 갱신): 헤더 아래 무한 스크롤 티커 바는 2026-08-02에 1차 구현·배포했으나, 2026-08-03 피드백으로 "나중에 추가"하기로 하여 제거함(코드는 git 히스토리에 보존, 커밋 `a7789d7`). 2단계 로드맵 항목으로 재분류.

## R4. 비기능

- 비용 0원 (무료 소스·무료 티어만)
- 홈 첫 로드 데이터 전송량은 summary.json 하나로 제한 (전체 5년 데이터 로드 금지)
- 디자인은 `docs/steering/design.md` 토큰 준수
- 대중 홍보·공유는 `docs/data-rights.md` 게이트 통과 전 금지

## 검증 계획

- Stage 1: Actions 러너에서 소스별 실 응답 확인, 값을 네이버 금융 화면과 스팟체크
- Stage 2: 3개월 수집 → 검증 통과 → 2회 연속 실행으로 증분·원자성 확인 → 5년 백필
- Stage 3: dev 서버 + 브라우저(claude-in-chrome)로 차트 값·MA 계산·모바일·stale 확인
- Stage 4: workflow_dispatch 일괄 성공 → 익일 장전·장후 크론 자동 실행 확인
