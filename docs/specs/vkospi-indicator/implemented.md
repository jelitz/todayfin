# Implemented — vkospi-indicator

## 설계 결정

- **VKOSPI는 파생 계산이 아니라 일반 외부 소스 지표**: KRX Open API `idx/drvprod_dd_trd`에서 직접 받으므로 collect.py에 특수 훅 없이 레지스트리 등록만으로 끝났다. summary·티커·상세는 기존 구조가 자동 처리(실제로 프론트 지표별 코드 변경 0줄 — SECTIONS 한 줄과 About 문구뿐).
- **`fetch()` 공용 일자 루프 재구성**: 기존 세 분기가 독립 컴프리헨션이라 백필 스로틀을 끼울 공용 지점이 없었다(설계 검증에서 확인). per-day 행 함수 + 공용 루프로 정리하고 30일 초과 범위에만 `sleep(0.15)` — kospi 등 기존 지표도 파일 유실 시 같은 보호를 받는다.
- **빈 `CLSPRC_IDX` 방어**: spike 실측에서 같은 응답 계열의 일부 지수가 종가를 빈 문자열로 주는 것을 발견. `_num("")`이 0을 돌려주므로 방어 없이는 "VKOSPI 0 폭락" 오염 데이터가 저장된다 — 빈 값이면 해당 일자를 건너뛴다.
- **IDX_NM 공백 무시 매칭**: 실측 표기는 "코스피 200 변동성지수"지만 제3자 구현들이 공백 변형을 보고한 바 있어 공백 제거 후 비교.
- **워크플로우 타임아웃 무변경**: 설계 초안은 "30분 설정"이었으나 적대적 검증에서 뒤집혔다 — `collect-and-deploy.yml`에 timeout-minutes가 없어 기본 360분이 이미 적용 중이고, 짧은 타임아웃을 넣으면 재시도 증폭(fetch 전체 ×3, 최악 ~45분) 시 첫 백필이 원자적 교체 전에 죽어 무한 반복 루프가 생길 수 있었다.

## 미결 질문

- KRX Open API 호출량 제한 정책이 미공개 — 백필 1,240회는 문제없이 통과할 것으로 예상하나 실측으로만 확인 가능. 문제 시 스로틀 강화 또는 범위 축소.
- VKOSPI는 T+1 공표라 항상 전 영업일 값이다. 기준일 표기가 이를 그대로 드러내므로 별도 처리 없음 — 사용자 혼동 리포트가 오면 재검토.
