# Requirements — home-two-column (홈 지표 테이블 반폭 2단 재배치)

2026-08-08 사용자 요청: "너무 다 세로 위주로 스크롤해서 봐야하다 보니 앞으로 지표가 추가되면
불편할 수 있어. 테이블의 가로 사이즈를 줄여서 두개의 테이블이 한 가로에 들어가도록 해줘.
예를들면 카테고리에 맞게 수급/변동성 리스크를 하나의 테이블 가로 사이즈로. (당연히 지금처럼
구분은 되어야 함) 시장 가격/추세는 국내 해외를 하나의 가로 테이블 가로 사이즈로 하는 방식."

인터뷰 확정(2026-08-08): 반폭 테이블은 **기준일 열만 제거**(지표·현재값·등락·추세·상세 유지).

## 요구사항

- **R1 (2단 블록 그리드)**: WHEN 데스크톱 폭 뷰포트에서 홈을 열면 THEN 시스템은 지표
  테이블을 반폭 블록 2단으로 표시해야 한다. 블록 단위는 섹션 또는 소그룹이며, 배치는
  사용자 예시를 따른다:
  | 좌 | 우 |
  |----|----|
  | 수급 (2행) | 변동성·리스크 (1행) |
  | 시장 가격·추세 — 국내 (4행) | 시장 가격·추세 — 해외 (4행) |
  | 거시·통화 — 환율·달러인덱스 (4행) | 거시·통화 — 미국 국채 (3행) + 한국 국채 (1행) |
  | 원자재 (2행) | (여백 — 향후 지표 추가 자리) |
- **R2 (구분 유지)**: 각 블록은 현행과 동일한 섹션 제목·소그룹 제목 위계(크기·색)를 유지해야
  한다. 같은 섹션이 좌우로 갈라지는 경우(시장 가격·추세, 거시·통화)에도 어느 섹션 소속인지
  제목에서 식별 가능해야 한다.
- **R3 (반폭 열 구성)**: 반폭 블록 테이블은 지표·현재값·등락·추세(스파크라인)·상세 5열로
  표시해야 한다. 기준일 열은 제거한다. stale 배지("N일 전 데이터")·장중 라이브 표시는
  이름 옆에 현행대로 유지한다.
- **R4 (반응형)**: WHEN 뷰포트가 2단 최소 폭 미만이면 THEN 블록을 1단으로 스택해야 하며,
  WHEN 모바일 폭(≤640px)이면 THEN 현행 모바일 규칙(추세 숨김·상세 아이콘만)을 유지해야 한다.
- **R5 (기능 동일성)**: 행 클릭 → 상세 모달, 상세 앵커의 키보드 접근성(Tab→Enter), 스켈레톤
  로딩, 등락 색상(빨강/파랑/회색)은 현행과 동일하게 동작해야 한다.
- **R6 (확장성)**: 새 지표·블록 추가가 `types.ts`의 배치 설정 수정만으로 반영되는 구조여야
  한다(컴포넌트 코드 수정 불필요).

## 검증 계획

- vitest: 배치 설정(전 지표 21개 누락·중복 없음), 블록 렌더 구조.
- 브라우저 실측: 데스크톱 2단·중간 폭 1단·모바일 열 숨김, 행 클릭·앵커 진입, 라이트/다크.
