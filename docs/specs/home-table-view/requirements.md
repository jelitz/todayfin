# Requirements — home-table-view

홈 기본 뷰를 카드 그리드에서 코인글래스식 컴팩트 테이블로 전환한다.

## 배경과 목적

현재 홈은 지표 카드(데스크톱 기준 약 200px 높이) 그리드로, 13개 지표를 보려면 화면 여러 장을 세로 스크롤해야 한다. 지표는 계속 늘어날 예정(VKOSPI 등)이므로 "한눈에 주요 지표 파악 + 30개+로 늘어나도 견디는 구조"가 필요하다(2026-08-08 사용자 요청).

인터뷰 결정(2026-08-08): 컴팩트 테이블 채택. 단, **"누르면 상세 모달이 열린다"는 것을 사용자가 오해 없이 알 수 있도록 아이콘이나 단어로 명확히 표기할 것 — 위치는 각 행 오른쪽**(사용자 노트 원문 반영).

## 요구사항

- R1. 홈 기본 뷰는 컴팩트 테이블이어야 한다. 섹션·소그룹(types.ts `SECTIONS`)은 그룹 헤더 행으로 유지하고, 지표당 1행 = 이름 · 현재값(단위 포함) · 등락(기존 색 규칙: +빨강/-파랑/보합 회색) · 스파크라인(기존 summary `spark` 그대로 — 최근 약 3개월) · 상세 어포던스.
- R2. 각 행 오른쪽 끝에 상세 보기 어포던스(아이콘 + "상세" 단어)가 항상 보여야 한다. WHEN 행을 클릭하면(행 전체가 클릭 대상) THEN 기존 상세 모달(`#/i/{id}`)이 열려야 한다.
- R3. 카드 뷰는 테이블로 완전히 대체한다(2026-08-08 리뷰 결정 — 토글 없음). `IndicatorCard` 컴포넌트와 홈 그리드 CSS는 제거하되, 스파크라인 렌더 로직은 테이블 행에서 재사용한다.
- R4. 반응형: 모바일(≤640px)에서 가로 스크롤 없이 표시돼야 한다 — 스파크라인 축소·숨김은 허용, 이름·현재값·등락·상세 어포던스는 유지.
- R5. 데스크톱(1440×900 기준)에서 현재 13개 지표가 스크롤 없이 또는 한 화면 남짓에 들어와야 한다(행 높이 목표 40~48px).
- R6. GNB·티커 바·상세 모달·다크모드 동작은 변경하지 않는다.
- R7. 접근성: 각 행의 상세 진입이 키보드로 가능해야 한다 — 행마다 Tab으로 도달·Enter로 활성화되는 상세 앵커(`#/i/{id}`)를 제공한다(기존 카드의 `role="button"`+수동 keydown 패턴은 앵커의 기본 동작으로 대체 — 더 단순하고 의미론이 정확함).

## 검증 계획

- vitest: 행 데이터 매핑(등락 표시 분기 — flows는 절대액, 그 외 %)
- 브라우저: 1440×900에서 13개 지표 한 화면 확인, 모바일 뷰포트(390px) 가로 스크롤 없음, 다크모드, 행 클릭→모달, 키보드 조작

## 범위 제외 (백로그)

- 지표 핀 고정·사용자 정렬(지표 30개+ 시점에 재검토)
- 히트맵 오버뷰(인터뷰에서 미채택)
