# Requirements — near-realtime-updates

승인 이력: 사용자 요청("실시간(완전 실시간 아니어도 됨)으로 보고 싶다") + 인터뷰(AskUserQuestion 2라운드) + 실측 스파이크(2026-08-03, naver/FDR/yfinance 실제 응답 확인) 결과 확정.

## 배경 — 기존 결정과의 충돌 및 정정

`docs/steering/product.md` 제약("갱신은 일봉 기준 하루 2회로 충분 — 실시간 시세는 비목표")을 뒤집는 요청. 실측 스파이크로 지표군별 실현 가능성이 다름을 확인:

| 지표군 | 실측 결과 | 실시간화 가능 여부 |
|---|---|---|
| 수급(investor_kospi/kosdaq) | 기존 naver 소스가 장중 호출 시 오늘 날짜의 잠정 순매수 행을 반환함(확인됨) | ✅ 기존 소스 그대로, 빈도만 증가 |
| 원/달러·달러/엔·WTI(yfinance) | 장중 호출 시 오늘 값이 전일과 다르게 갱신됨(확인됨) | ✅ 기존 소스 그대로, 빈도만 증가 |
| 코스피·코스닥·삼성전자·SK하이닉스(FDR) | 장중 호출해도 최신 행이 지난 거래일에 고정(FDR이 하루 1회 갱신 정적 캐시를 읽는 구조) | ❌ 기존 FDR 소스로는 불가 → 신규 소스 필요(아래 R3) |
| 미국채 2/10/30년·국고채 3년 | 정의상 하루 1회 고시되는 공식값(Daily Par Yield, 최종호가수익률) | — 실시간 개념이 성립하지 않음, 스코프 제외(사용자 결정 불필요할 만큼 명확) |

## R1. 대상 지표

WHEN market_hours 수집 프로필이 실행되면 THEN 시스템은 아래 9개 지표만 수집해야 한다: `investor_kospi`, `investor_kosdaq`, `kospi`, `kosdaq`, `samsung`, `skhynix`, `usdkrw`, `usdjpy`, `wti`.

국채 4종(`ust2y`/`ust10y`/`ust30y`/`ktb3y`)은 market_hours 대상에서 제외하고 기존 장전/장후 하루 2회 수집을 그대로 유지한다(위 배경 표 참조 — 값 자체가 하루 1회만 갱신되므로 더 자주 조회해도 의미 없음).

## R2. 수집 주기·시간대

- WHEN 평일(월~금) 정규장 시간(KST 09:00~15:30) 중이면 THEN 시스템은 30분 간격으로 market_hours 프로필을 수집해야 한다
- 장외 시간대·주말은 기존 장전(KST 08:10, 월~토)·장후(KST 18:40, 평일) 크론을 그대로 유지한다(변경 없음)
- market_hours 수집은 기존 장전/장후 수집과 독립적으로 동작하며 서로의 스케줄을 방해하지 않는다

## R3. 코스피·코스닥·삼성전자·SK하이닉스의 실시간 소스

- WHEN market_hours 프로필이 `kospi`/`kosdaq`/`samsung`/`skhynix`를 수집하면 THEN 시스템은 신규 네이버 실시간 시세 폴링 API(`polling.finance.naver.com`, 비공식)에서 현재가·시가·고가·저가·누적거래량을 가져와 **오늘 날짜 1행만** 기존 시계열에 병합(교체)해야 한다
- 과거(어제 이전) 확정 일봉은 기존 FDR 소스로 유지하며, market_hours 수집이 과거 데이터를 건드리지 않는다
- IF 실시간 소스 응답이 기존 OHLC 불변식 검증(`validate.py`)에 실패하면 THEN 시스템은 오늘 행을 갱신하지 않고 기존 값을 유지해야 한다(데이터 정확성 우선 원칙 — product.md 핵심가치 1순위)

## R4. 프론트 자동 갱신

- WHEN 홈 화면이 열려 있으면 THEN 시스템은 5분 간격으로 `summary.json`을 백그라운드로 재조회해 카드 값·등락·스파크라인을 새로고침 없이 갱신해야 한다
- WHEN 브라우저 탭이 비활성(숨김) 상태이면 THEN 자동 재조회를 일시 중단해 불필요한 요청을 줄여야 한다(`document.visibilitychange` 활용)

## R5. 장중 데이터 표시

- WHEN 지표의 `observed_last`가 오늘 날짜이고 해당 지표가 R1의 9개 대상에 포함되면 THEN 카드(및 티커 항목)에 장중 갱신 중임을 나타내는 표시(예: 작은 펄스 점 + "장중" 라벨)를 노출해야 한다 — 정식 확정치(전일 마감 이후 값)와 시각적으로 구분하기 위함
- 이 판단은 백엔드 스키마 변경 없이 프론트에서 `observed_last === 오늘(KST)` + 지표 ID 목록만으로 계산한다

## R6. 데이터 권리

- 신규 네이버 실시간 시세 API는 비공식 소스이므로 `docs/data-rights.md` 매트릭스에 기존 수급 소스(네이버 금융)와 동일한 리스크 카테고리로 항목을 추가해야 한다
- MVP 공개 수위 원칙(비홍보 개인 운영)은 변경하지 않는다

## 비기능

- 비용 0원 원칙 유지 — GitHub Actions 무료 티어(공개 저장소 무제한 분) 범위 내
- market_hours 수집 실패(네이버 API 차단·구조 변경 등)는 해당 회차만 skip하고 기존 값을 유지해야 하며, 장전/장후 정규 수집에 영향을 주지 않아야 한다
- 데이터/git 히스토리 증가: 거래일당 최대 14회 추가 커밋·배포 발생(월 약 250~300건) — 수용 가능한 트레이드오프로 기록(implemented.md)

## 검증 계획

- 실제 GitHub Actions에서 market_hours 워크플로우를 1회 이상 실행해 실측 확인(로컬은 시간대·시장개장 여부 재현 어려움)
- 로컬에서 `naver_realtime.py` 단독 실행으로 응답 스키마·파싱 정상 동작 확인
- 프론트 폴링은 브라우저(claude-in-chrome)로 5분 대기 대신 인터벌을 임시로 단축한 개발 빌드로 동작 확인 후 원복
