# Requirements — news-page (뉴스 페이지 신설)

2026-08-08 사용자 요청: "뉴스 페이지를 새로 신설하고 거기에 뉴스를 뜨도록. 디자인은 토스증권
뉴스 피드(tossinvest.com/feed/news) 벤치마크하되 우리 사이트 디자인 철학에 맞게. 단, 뉴스
페이지에서도 상단 5개의 헤드라인은 메인 페이지에 뜬 것처럼 고정하고 살짝 구분감."

인터뷰 확정(2026-08-08):
- 피드는 토스처럼 **주요뉴스/최신뉴스 탭 2개**로 나누고 구성·정렬을 달리한다. 토스의
  인기뉴스·급상승뉴스는 조회수·주가 데이터가 필요해 대응 불가 — 우리 신호(구글 랭킹·발행
  시각) 2개에 정확히 대응하는 탭 2개만.
- **텍스트 피드** — Google News RSS에 썸네일·요약이 없고, 원문 og:image 크롤링은 권리
  리스크·복잡도로 배제. 데이터 권리 완화책("본문·이미지 미수록")도 유지된다.
- **전체 건수 노출 + data-rights.md 갱신** — 기존 완화책의 "5건 제한" 문구는 피드 제공
  범위 내 표시로 완화 서술을 갱신(개인 운영·대중 공유 게이트 전제는 불변).
- 아키텍처 = **스냅숏 + 클라이언트 정렬**(A안): 수집 상한만 5→70, news.json 스키마 불변,
  탭 정렬은 프런트 순수 함수. 축적 아카이브(B안)는 병합 상태·URL 중복 판정 리스크로 배제.
- 하단 티커 바는 뉴스 페이지에서도 **노출**(시장 컨텍스트 페이지로 취급).

## 요구사항

- **R1 (라우트·GNB)**: `#/news` 해시 라우트와 GNB "뉴스" 탭을 추가해야 한다. 탭 순서는
  홈 / 뉴스 / 소개 / 알상무. 활성 판정은 기존 라우트 대조 방식.
- **R2 (헤드라인 고정 블록)**: 뉴스 페이지 상단에 홈과 동일한 "주요 뉴스" 5건 블록을
  고정해야 한다 — 동일한 행 문법(KST 시각 + 출처명 + 제목 링크)에 배경만 `--surface`로
  달리해 아래 피드와 구분감을 준다(그림자·그라디언트 금지 원칙 유지).
- **R3 (탭 피드)**: 헤드라인 블록 아래에 주요뉴스/최신뉴스 탭을 제공해야 한다. 기본 탭은
  주요뉴스.
  - 주요뉴스 = 구글 랭킹순(수집 배열 순서). 상단 고정 5건과의 중복을 피해 **6번째부터** 표시.
  - 최신뉴스 = **전체** 항목을 발행 시각 내림차순 정렬(타임라인 완전성 — 고정 5건 포함).
  - 행 = 메타 라인(출처명 · **KST "MM.DD HH:MM"** — 2026-08-08 사용자 피드백: 시간뿐
    아니라 날짜도 상시 표기, 초판의 상대 시각 폐기) + 제목(최대 2줄, 초과 말줄임).
    클릭 시 새 탭 원문(`rel="noopener noreferrer"`). 헤드라인 블록(홈 포함)의 시각도
    동일 형식으로 날짜 상시 표기.
  - **페이지네이션**(2026-08-08 사용자 피드백): 피드는 페이지당 20건, 목록 하단 번호
    버튼으로 이동. 탭 전환 시 1페이지로 리셋.
  - WHEN 탭에 표시할 항목이 0건이면 THEN "더 표시할 뉴스가 없습니다" 문구를 표시해야 한다.
- **R4 (수집 확대)**: 매시간 뉴스 수집 상한을 5→70으로 확대해야 한다. `data/news.json`
  스키마(배열 순서 = 구글 랭킹)는 불변. 실패 시 기존 유지·24h stale `::warning` 정책 승계.
  홈 헤드라인 블록은 여전히 상위 5건만 표시한다(기존 `slice(0, 5)` 유지).
- **R5 (갱신·회복력)**: 뉴스 페이지는 news.json을 5분 주기로 폴링해야 한다. 상태는 3가지로
  구분한다(2026-08-08 적대적 검증 반영 — 로딩을 실패로 오판하면 진입 때마다 오류 문구가
  플래시된다):
  - WHEN 첫 응답 전(로딩 중)이면 THEN 안내 문구를 표시하지 않아야 한다(빈 본문).
  - WHEN 한 번도 로드에 성공하지 못했거나(파일 부재 포함) generated_at이 24시간을
    초과하면 THEN 안내 문구를 표시해야 한다(홈은 기존대로 블록 숨김 — 페이지 전체가
    뉴스인 곳에서만 문구).
  - 첫 성공 이후의 일시 실패는 기존 값 유지(usePolledJson 정책 승계 — error 미발생).
  지표·GNB 등 나머지 UI는 영향 없어야 한다.
- **R6 (티커 바)**: 뉴스 페이지에서 하단 티커 바를 노출해야 하며, 노출 라우트의 shell 하단
  패딩 규칙을 승계해야 한다. 티커 항목 클릭은 기존 메커니즘 승계 — 홈+상세 모달로 이동하고
  모달을 닫으면 홈에 남는다(뉴스 페이지 복귀 없음 — 2026-08-08 검증에서 지적됐으나 라우트
  구조 변경 비용 대비 수용).
- **R7 (홈 더보기)**: 홈 주요 뉴스 블록 제목 행 우측에 "더보기" 링크(`#/news`)를 추가해야
  한다.
- **R8 (데이터 권리)**: `docs/data-rights.md` Google News 행의 완화책 문구를 갱신해야
  한다 — "5건 제한"을 "피드 제공 건수 내(~70건) 헤드라인·출처·시각·링크만 표시(본문·이미지
  미수록)"로. ⚠️ 대중 공유 게이트 항목 지위는 유지.
- **R9 (테마·모바일)**: 전부 테마 토큰만 사용해 다크모드 자동 대응, 모바일에서 기존 규칙
  (헤드라인 블록 출처 숨김 등)을 승계해야 한다.

## 비요구사항 (하지 않음)

- 썸네일·요약·본문 수록, 원문 크롤링 — 텍스트 피드만.
- 카테고리(토픽) 추가 피드, 인기뉴스·급상승뉴스 탭 — 데이터 없음.
- 무한 스크롤 — 페이지네이션(20건/페이지, 2026-08-08 개정)으로 대체. ~~전체 렌더~~는
  초판 결정이었으나 사용자 피드백으로 폐기.
- 탭 상태 딥링크(`#/news?tab=…`) — 로컬 상태만.
- 축적 아카이브(과거 뉴스 보관) — A안 채택으로 배제.

## 검증 계획

- vitest: 상대 시각 경계(방금 전/59분/60분/23시간/24시간/6일/7일·미래 시각 가드), 정렬
  순수 함수(내림차순·안정성), NewsView 렌더(고정 5건·주요뉴스 탭 6번째부터·initialTab
  주입으로 최신뉴스 정렬·새 탭 속성·source null 행·빈 탭 문구), News 상태 분기(로딩 중
  문구 부재·stale 안내 문구), route `/news` 파싱, 홈 더보기 링크.
- pytest: 기존 테스트 유지(파싱 로직 불변 — limit 상수만 변경).
- 로컬 수집 스모크(스크래치, limit 70 실측) → 로컬 브라우저 실측 → 배포 실측(탭 전환·원문
  도달).
